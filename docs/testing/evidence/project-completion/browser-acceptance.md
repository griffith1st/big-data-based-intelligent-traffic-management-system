# 智能交通系统浏览器验收（2026-10-17）

环境：Windows 本机 Chromium，Playwright CLI 会话 `itms-completion`，1440×1000；前端 `http://127.0.0.1:13000`，后端 `http://127.0.0.1:18080`。

## 已确认

- 初始 Docker 部署六个服务均 healthy，浏览器经 Nginx 同源登录 admin 成功，`/api/auth/me` 返回并显示服务器身份。
- 全新数据库中，读取监控大屏不会隐式生成交通或预测数据；空态清楚。
- 管理员通过“生成一批模拟交通数据”按钮写入 Kafka；数据库查询确认 56 条记录、14 个路口，前端显示 SIMULATOR 来源及真实采样时间。
- 预测页通过按钮生成批次；展示未来 30 分钟、6 个时间点及 SIMULATION-v1 标识，没有虚构准确率。
- 配时页：应用按钮最初禁用；计算候选后当前表仍为 90 秒，候选为 101 秒；点击应用后当前变成 101 秒，候选清空，应用按钮重新禁用。
- 管理员通过真实表单完成路线规划，显示 3.35 km、估算时间和碳排放；自己的历史增加 1 条。
- 后端暂时不可用时，交通页面显示持续错误、尚无成功记录与“—”指标，保留刷新入口。
- 最终源码 Jest：7 suites、25 tests 全部通过；`npm run build` 通过，主文件 `main.a20d950c.js`。
- 最终源码修复规划边采样未知的显示，并覆盖实际 LOW_CARBON 枚举和旧 GREENEST 历史兼容。

## 环境切换

初始 Docker 浏览器流程成功后，最终镜像重建与主机测试重叠时发生内存压力，Docker BuildKit 报 RPC EOF。官方 Desktop 重启及清理残余 host 进程后的启动都在 sailor-ingest.sock 的自动改名步骤失败。未删除该 socket、未重置 Docker 数据。

为继续验证，最终生产前端构建通过 `serve-demo.mjs` 提供 SPA 静态资源，并将 `/api/` 同源代理到后端 18080。该文件仅用于本机演示，生产仍用 frontend/nginx.conf。脚本仅监听 127.0.0.1，已实测 `/route` SPA 和 JS 的 HTTP 200、正确 MIME。

用户新增的首次浏览器尝试恰逢上述引擎故障，返回请求超时；本报告中的 CRUD 成功证据来自下方原生环境的重新验收。
