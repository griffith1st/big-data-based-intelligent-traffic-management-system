# 智能交通项目完善计划与验收记录

目标：完善现有项目的核心业务、访问权限、数据一致性、前端操作和部署验证，并同步更新现有说明与学习材料。保留 Java / React / PostgreSQL / Redis / Kafka 架构，所有功能描述以实际运行结果为准。

## 完整使用闭环

1. 新环境按文档启动，健康检查通过，缺少依赖时有明确诊断。
2. 管理员登录、创建账号、修改权限/密码、禁用账号和退出；普通用户的访问范围由服务端执行。
3. 交通数据生成/接收后保存，页面展示最新与历史数据，告警可查看、已读和处理。
4. 预测产生可解释的演示结果，信号方案计算并保存、应用，路线按当前路况计算并保存个人历史。
5. 多个用户或消息同时进入时，验证关键事务、去重、缓存与资源保护。
6. 失败与空数据在页面上有可理解的反馈，审计记录能追踪操作者。
7. 测试、部署、项目边界与学习文档覆盖上述实际功能。

## 验证证据要求

- 回归测试记录实际数量、失败/跳过和运行命令；保留历史并发报告，新增结果另记。
- 使用隔离 PostgreSQL、Redis 和 Kafka 验证真实业务链路；Mock 测试不替代外部组件证据。
- 前端构建、角色操作与核心页面进行运行验证；将可复现缺陷转为回归用例。
- 验收逐项对应上述闭环，尚未验证的项保持未完成，不用单项绿测代替整个项目完成。
- 最终核对 Git 差异，提交到 griffith1st 仓库，验证远程提交；不修改 upstream 仓库。
